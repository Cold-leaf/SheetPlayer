# SheetPlayer 谱音同步播放器

在五线谱 PDF 上标记小节、按音频打时间点，播放时谱面跟随高亮滚动。单 HTML 文件实现，可安装成 PWA（独立全屏、离线可用、数据持久）。

- **排练场景工具**：暗色克制配色，收起工具栏进入「排练模式」——谱面全屏，底部只留一条极简胶囊。
- **一份谱子，多套时间点**：同一个 PDF 可以挂多个音频（不同声部/伴奏/演出场次），各自一套时间点。
- **数据留在本机**：谱子和音频存浏览器 IndexedDB，只有标注（几十 KB）可以走 GitHub 仓库跨设备同步。

---

## 核心概念

一个**曲目** = 1 个 PDF + N 个音频变体 + 1 份标注（小节位置 + 时间点）。

| 概念 | 说明 |
|---|---|
| 小节标记 | 每根竖线在谱面上的位置（第几页 + 横纵坐标），**一份谱子共用一套** |
| 时间点 | 每个小节对应音频里的时刻，**按「模式」分套** |
| 模式 | 同一谱子的多套时间点，如「标准」（MIDI 转出）/「现场」（演出录音）；切音频自动切到它所属的模式 |
| 段落 | 自动从时间点切出来的「遍」——小节号往回跳 = 新的一遍（反复/返场），点段落条可跳段 |
| 播放列表 | 选定若干曲目（可各自指定音频版本）连播 |

**项目才是身份**，PDF 只是挂在它下面的一件附件（音频同理）。跨设备认的是**项目名 + 别名**；PDF 的内容哈希（前 1MB SHA-256）只在两处用：导入时的去重与认领、以及本机存 blob 的键。所以换谱子、改文件名都不丢标注，同一个项目在两台设备上也能对上。

## 快速上手

1. 打开后进入「曲目库」，点「**＋ 新建项目**」起个名字，再在它那一行点「**＋ 导入谱子**」选一份 PDF。（如果不在乎项目叫什么，也可以直接走 ☰ 菜单 →「谱子 → 导一份新谱子」，它按文件名认领已有项目、认不上就新建。）
2. 给曲目挂音频：工具栏「音频」下拉 →「＋ 添加音频…」，选文件后弹窗选它属于哪个模式（选「新建」可输入新模式名）。
3. 切到「**标小节**」模式，在谱面上逐个小节点出每根小节线（竖线会自动吸到印刷的小节线）。嫌慢就把工具栏上的「**整行补齐**」勾上（只在标小节模式下出现），点一下行首补齐整行。
4. 切到「**打时间**」模式，播放音频、在每个小节线上点一下（或按空格）记录该小节的开始时刻。
5. 切回「**播放**」模式，谱面随播放高亮滚动；点任一小节可跳转。

只标了位置、不想逐小节打点？用「**自动生成**」按速度表 + 拍号 + 播放顺序一键生成整条时间轴（详见下文）。

## 五种工作模式（工具栏「工具」下拉）

| 模式 | 做什么 | 交互 |
|---|---|---|
| **播放** | 听、跟谱 | 点竖线跳到当前段落的那一遍；2 秒内再点同一个点换到下一遍 |
| **标小节** | 标每根小节线的位置 | 点谱面加点。勾上工具栏的**「整行补齐」**就是半自动：点一下行首，自动检测该行剩余印刷小节线、一次补齐整行 |
| **打时间** | 记录每小节的开始时刻 | 点竖线记时间（Shift+点 = 只把目标移过去不记）；空格/回车给当前目标小节打点并前进 |
| **编辑点** | 微调竖线 | 拖竖线中段挪位置，拖两端改长度，单击开面板（可设高度并套用） |

「整行补齐」不是一个单独的模式，而是「标小节」模式下的一个开关——**只在标小节时出现在工具栏上**，切走就藏起来。手动标和半自动标是同一条流程的疏密两档，来回切的时候不用丢掉「标小节」这个身份。开关默认关。

工具栏第 1 行的「撤销 / 自动生成 / 频谱」按模式显隐：撤销在所有编辑类模式出现；自动生成和频谱只在打时间模式出现。

## 工具栏布局

- **第 1 行**：曲目 / 工具 / 整行补齐（**只在标小节模式下出现**）/ 撤销·自动生成·频谱（按模式）/ 曲目库 / ☰ 菜单 / ▲ 收起
- **第 2 行**：播放键 + 时间（自制精简条，无音量）/ 音频 / 删音频 / 模式 / 速度 / 跟随滚动 / 播放列表条
- **第 3 行**：「现在 小节 N」+ 目标指示 / 段落 chips / 练习循环（起点 · 终点 · 循环 · 区间）

横向 / 纵向的切换在**菜单「视图」**里，是一个**按钮**不是勾选框：文案显示**当前**方向（「横向铺开」/「纵向堆叠」），点一下翻过去。用按钮而不是勾选框，是因为勾选框只写得出「横向铺开」这一个词——找"横竖切换"的人扫过去就划走了。真正的状态其实是个 hidden 的 `#chkHoriz`，按钮只是它的 `.click()` 壳（跟 `#fPdf` ↔ label 同一套写法），`bFitW` 和初始方向那几处都读它。

方向为什么不在工具栏：第 1 行在 390px 真实路径下只剩 2px 余量（菜单右沿 344 / 内容右沿 346），塞一个 78px 的按钮挤掉的正是「☰ 菜单」——而菜单是手机上通往一切设置的入口，方向按钮现在就住在里面。

初始方向按当前窗口宽决定——≤700px 纵向堆叠、更宽横向铺开，跟窄屏版式是同一条断点，所以窄窗口天然是「一页一行 + 横滑」。**不持久化**（跟「显示编号 / 小节进度 / 跟随滚动」一致），刷新即回按宽度算出来的那个值；旋转屏幕也不会重算，初始方向在一次会话里是稳定的。

窄屏窗口，以及**任何宽度**的触摸设备（手机 / iPad 竖屏横屏 / 触屏笔记本），每行横向滑动、不折行；触摸设备上触控目标一律 44px。桌面鼠标在宽窗口下保持紧凑密度、内容折行铺开。曲目/音频下拉在长名字时封顶收短（悬停可见全名），存储原名不动。

两个判断是分开的，别混：**目标尺寸**看 `(pointer:coarse),(any-pointer:coarse)`——插着鼠标但屏幕能摸，手指照样要点得准；**版式**看 `(max-width:700px),(pointer:coarse)`——版式这条不带 `any-pointer`，触屏笔记本的主输入还是鼠标，不该变成手机排版。

横向滑动而不折行，是因为折行会把段落条顶成好几行，段落越多越高：实测 4 个段落时 iPad 竖屏工具栏要吃掉 22–28% 屏高（无段落时 14%），横滑后恒定在 168px。段落多到放不下时横向划一下就能看到其余的。

## 排练模式（收起工具栏）

点「▲」收起工具栏，谱面全屏，底部出现悬浮胶囊：

```
[⏮][▶][⏭]  ─────────进度条────────  曲名·模式  [0.8×] [⌃]
```

- 播放/暂停、上/下一首（播放列表进行中时可用）
- 进度条**可点可拖**走带；时间 + 曲名实时显示
- **`0.8×`** 是倍速选择器：原生下拉涂成一个 **44px 的圆**，跟旁边 ⏮ ▶ ⏭ ⌃ 一套语言（原来按最宽档位「1.25×」撑成 78px 的胶囊，太占地方）。档位跟工具栏那个「速度」一模一样，平板上点开就是系统的选择器（大目标、跟系统深色模式走），桌面上就是普通下拉。圆里放不下下拉箭头，改用 hover / 按下时的底色提示可点
- 手机窄屏自动折成两行（控制组一行、曲名+倍速一行），进度条和曲名各占整行
- 点「⌃」展开工具栏

## 自动生成时间轴

菜单或打时间模式点「自动生成」。只生成**时间**，小节在纸上的**位置**仍要自己标。手动卡的时间点会被当成硬锚点保留，生成的时间在锚点之间按比例拉伸对齐。

- **速度**：整曲一行 BPM（变速处加一行，写从第几小节起）。
- **拍号**：一种拍号一行，后面写它管哪些小节（`1, 3, 5-25, 27`；**留空**的那行兜底管其余全部）。
- **播放顺序**：留空 = 全曲从头到尾一遍；有反复就写 `1-8, 3-8, 9-12`（每段一个小节区间）。
- **锚点**：决定整条时间轴的绝对位置。默认用已卡的实测点；也能手动指定一个（整轴按速度表平移）。

生成面板会体检锚点：相邻锚点之间「实际用时 ÷ 速度表预测用时」偏离 1 太多（比如 ×2.28）会标黄提醒——通常是某个锚点卡歪了，或那一段的 BPM/拍号填错了。

> 扫描/影印版谱子（谱线发灰不连续）打开时会提示：半自动标小节可能不准，建议手动标，或换数字排版版。

## 曲目库与数据管理

曲目库里的东西叫**项目**。项目才是身份，**名字**是它在各设备之间对得上的凭据；**PDF 和音频都是可以随时换的附件**——标注绑在项目上，换谱子不会丢。

- 每张卡片：**打开** / **加入列表** / **换谱** / **改名** / **删除**；显示已标小节数、各模式时间点数、音频数、更新时间。
- **新建项目**：先起个名字，谱子稍后补。项目才是身份，谱子和音频都是挂在它下面的附件——所以建条目是第一动作。
- **导入谱子**：还没有谱子的项目，卡片上第一格就是它（有谱子之后变回「打开」）。选了 PDF 就**挂到这一条上**，不靠文件名猜。
  另一边 ☰ 菜单 →「谱子 → **导一份新谱子**」是"随手导一份"的入口：文件名（或内容）对得上已有项目就挂上去，对不上就**建新项目**（项目名取文件名，去掉 `.pdf` 和下载器尾缀）；撞名时会当场问你要不要换个名字。
- **换谱**：换成另一份谱子（比如加完笔记重新导出的那份），**标注一个小节都不会少**，旧谱子进历史（留着最近 3 份，随时换得回来）。新谱子页码整体错位的话用菜单里的「整页平移」挪一下。
- **改名**：改的是项目名，**老名字会保留为别名**，所以改名是无损的——之后按老文件名重新导入谱子、或对端还按老名字同步回来，都能认回同一个项目。新名字和其他任何项目的名字/别名撞了会被拦下（撞名会让同步分叉成两个项目）。
- 顶部：新建项目 / **ownCloud**（从 WebDAV 下载，见下节）/ 导出全部标注 / 导入全部标注 / 从 GitHub 同步 / 清理历史谱子。
- 「占用」显示 IndexedDB 用量。

> 音频同理由「＋ 添加音频…」挂到项目上，可以按模式挂多个版本；音频文件不在本机时只会提示，不影响标注。

## 跨设备同步（推荐）

标注走 GitHub 仓库同步，**文件留在各设备本地**：

1. **桌面**（标注主设备）：曲目库「导出全部标注」下载 JSON。
2. 打开仓库网页 → 拖拽上传覆盖根目录 `annotations.json` → commit。
3. **平板/手机**：曲目库点「从 GitHub 同步」→ 自动拉取合并（按时间戳保留较新的，本地较新不会被旧数据覆盖）。

同步下来的是**项目**（名字 + 标注），PDF 文件仍要各设备自己导一次。对端点「打开」选那份 PDF 时，会按下面几步认回正确的项目，认回后时间点和竖线照旧：

1. 内容哈希正好是某个项目在用的谱子 → 就是它；
2. 是某个项目用过的历史谱子 → 问一句要不要换回去；
3. 文件名对得上项目的名字或别名 → 挂上去（**文件名命中不是改名**，项目名不会跟着文件跑）；
4. 都不中 → 用文件名当项目名建新项目。

所以改完名字记得**重新导出 + 提交**，对端才能看到新名字；不过就算忘了，对端还按老名字报，也会因为老名字在别名表里而认回同一个项目，不会分叉成两个。

> ⚠️ 仓库是公开的，`annotations.json` 里的练习标注（标了哪些小节等）也是公开可见的。

## 从 ownCloud（WebDAV）下载谱子 / 音频

曲目库顶部点「**☁ ownCloud**」，直接浏览服务器上的曲目库并下载——**只读**，不会往服务器写任何东西。

**登录**：点「☁ ownCloud」后面板里就有登录区（没登录过会自动展开；之后随时点「⚙ 登录」改）：

| 方式 | 服务器填 | 「用户」填 | 「密码」填 |
|---|---|---|---|
| **代理（Worker）**（推荐·最安全） | Worker 地址 `https://xxx.workers.dev` | 不用填 | 访问令牌（可选，见下） |
| **公开分享** | `https://服务器/owncloud` | 分享令牌 | 分享密码（没有就留空） |
| **账号** | `https://服务器/owncloud` | 你的用户名 | **应用密码**（不要用主密码，可随时吊销） |

> ⚠️ **有些服务器用不了「账号」和「公开分享」两种方式**：ownCloud 的 WebDAV 响应不带 CORS 头
> （只有 OPTIONS 预检带），浏览器会拦成 "Failed to fetch"。这不是密码问题——把地址粘到浏览器
> 地址栏能直接列出文件就说明凭据没问题。这种情况用下面的 **Worker 代理**。

公开分享令牌的拿法：在 ownCloud 里对该文件夹「创建公开链接」得到的令牌串。点「保存并登录」会直接列目录，成功与否一眼可见。

### 用 Worker 代理（服务器不支持跨域时的正解）

仓库里的 `dav-proxy-worker.js` 是一个 Cloudflare Worker（免费版够用），它站在中间转发请求、
补齐 CORS 头，**并且把账号密码存在 Worker 的加密密钥里——密码根本不下发到设备**。

部署（网页操作，不用装工具）：

1. dash.cloudflare.com → Workers & Pages → Create → Worker，把 `dav-proxy-worker.js` 内容整个粘进去，Deploy。
2. 该 Worker → Settings → Variables and Secrets，添加 **Secret**：
   `DAV_URL`（ownCloud 设置页给的那串 WebDAV 地址）、`DAV_USER`、`DAV_PASS`（应用密码）、
   `ALLOW_ORIGIN`（`https://cold-leaf.github.io`）、`TOKEN`（可选，设了要在 App 的「密码」框填同样的值）。
3. App 的 ownCloud 面板里，方式选「**代理（Worker）**」，服务器填 `https://<名字>.<账号>.workers.dev`。

好处：① 绕开 CORS；② 密码不在设备上，换设备/丢设备都不怕；③ 服务器地址和账号对客户端完全不可见。
Worker 只实现了 `PROPFIND` + `GET`（只读），写方法一律拒绝。

> **凭据存在哪**：直接连 WebDAV 时存在**你这台设备的 IndexedDB**里；用 Worker 时密码只存在 Worker 端，设备上只有 Worker 地址。
> 说明：GitHub Pages 是纯静态托管，没有服务端运行时，所以做不到 Actions secret 那种「存在服务器上、运行时注入」——但「不进仓库 + 别人看不到」这两个效果是等价的。注意 IndexedDB 按源隔离，源是 `cold-leaf.github.io`：如果你在这个域名下还有别的项目页面，理论上它也能读到；介意就用公开分享令牌（可随时吊销）。

**用法**：点文件夹进目录，点文件名即下载并导入——

- **PDF** → 走本机导入同一条路径：哈希去重、同名自动接回已有标注（时间点/竖线照旧），面板自动关闭并打开该谱。
- **音频** → 挂到**当前打开的曲目**上（会先问挂哪个模式）。所以下载音频前要先打开对应曲目。
- 其他格式会被拦下。

下载有进度显示（音频文件大，慢服务器上能看到百分比）。文件下载后存在本机 IndexedDB，排练现场**没网也能用**。

> 实现说明：只用 `PROPFIND` 列目录 + `GET` 下载，不发起任何写请求；跨域靠服务器返回的 `Access-Control-Allow-Origin`，ownCloud 默认已开启。

## 键盘快捷键（焦点不在输入框时生效）

| 键 | 功能 |
|---|---|
| 空格 / Enter | 打时间模式：给当前目标小节打点并前进；其他模式：播放/暂停 |
| Backspace | 撤销 |
| `[` `]` | 打点目标 −1 / +1 个小节 |
| ← → | 后退/前进 2 秒（按住 Shift 为 5 秒）|
| K | 播放/暂停 |
| `-` `=` | 减速 / 加速 |
| 0 | 速度归 1 |
| H / Esc | 开关帮助 |

鼠标/触摸：双指（或触控板 Ctrl+滚轮）缩放并锚定手指位置；谱面四周留白约一屏，可以像一张纸一样**拖到视口内任意位置**（拖到顶/底/边也不会卡死）。

## 部署到 GitHub Pages

1. 仓库 Settings → Pages → Source 选 **Deploy from a branch** → 分支 `main`、目录 `/ (root)` → Save。
2. 站点地址 `https://<用户名>.github.io/SheetPlayer/`。
3. 仓库须公开（GitHub Pages 免费账户硬要求）；部署的只是播放器外壳，谱子/音频永不上传。

安装成 PWA：手机/桌面浏览器「添加到主屏幕 / 安装应用」→ 独立图标、全屏、离线可用。**改过图标后需重新添加到主屏幕**（桌面图标是安装时抓取的）。

应用内也有入口：☰ 菜单 →「📲 安装到主屏幕」，里面按浏览器（Safari / Chrome / Edge）分了步骤，并且会把上面那句「改过图标要重新添加」再提醒一次。

这个入口**一直显示**，不会因为「已经装过」而藏起来：判断装没装靠的是 `matchMedia('(display-mode: standalone)')` 和 iOS 的 `navigator.standalone`，而有些 App 内置浏览器的 WebView 也会报 `standalone`，判错的代价是不对称的——藏错了用户就彻底找不到入口，多显示了只是卡片里多一句话。所以改装过时只在卡片里加一句说明。

顺带：菜单里这栏还有一行**构建号**（跟 `sw.js` 的 `VER` 一起 bump）。手机上「某个新功能看不到」时，先念这行就能分清是没发到、还是这台设备的缓存没刷掉。

## 开发

- 源码即 `player.html` 单文件（CSS + JS 内联）。PWA 外壳：`manifest.json` + `sw.js` + `icon-*.png` + `index.html`（站点根重定向）；`lib/` 是本地化的 pdf.js（3.11.174），离线也能渲染。
- 发布改动了内容记得 bump `sw.js` 里的 `VER`，否则旧缓存不清、用户拿不到更新（页面走网络优先一般能自动更新，但静态资源走缓存优先）。
- 测试在 `tests/`：
  - `tests/t*.js`：纯逻辑测试。t9 直接从 player.html 提取 `/*PURE*/` 块测真实代码；其余为手工拷贝的函数快照。
  - `tests/pw_*.py`：Playwright 浏览器端到端测试（`?direct=1` 参数跳过曲目库、走传统 localStorage 路径；库功能由 `pw_lib*.py` / `pw_migrate.py` / `pw_idbnull.py` 覆盖）。
  - 一键跑全套：`bash tests/run-tests.sh`（grep 输出中的 FAIL，任一失败 exit 1）。
- 测试里的 PDF/音频路径指向本机 `data/assets/`，换机器需改 `ROOT`。

## 数据说明与降级

- **曲目库**（IndexedDB，库名 `sheetplayer`）：标注按 PDF 内容哈希关联；PDF/音频文件副本、频谱分析缓存也在库里。
- **降级**：IndexedDB 不可用（隐私模式）自动退回 localStorage 按文件名存档；localStorage 也不可用则退内存 + 一次性警告（记得用「导出本曲标注」）。
- **老数据迁移**：旧版 localStorage 存档（`player:<文件名>` 键）启动时自动扫进曲目库，等对应 PDF 打开、哈希解析完成后再清老键。
- 单曲的「**导出本曲标注** / **导入本曲标注（覆盖）**」保留可用，导出带 `pdfHash` 字段用于校验谱子对不对。
  **跟上面那两个别混**：库里的「导出全部标注 / 导入全部标注」是**整库**、导入时**按时间戳合并**；菜单里这两个是**单曲**、导入时**整体替换**当前曲目（替换前存了快照，可撤销）。
